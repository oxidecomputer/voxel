# Voxel - engineering roadmap

Voxel (Virtual OXide Emulated Laboratory): an operator-focused evolution of a4x2
for planning, commissioning, and evolving Oxide deployments - operators pick an
Oxide platform *version* + a topology and launch, GNS3/Container-Lab style.

> The product docket (networking-docket -> voxel.html) is the canonical plan.
> This file is the engineering roadmap + the decisions made while building it.

## Shipped

### Foundation - image build, config, first bring-up
- **Snapshot-first image build** (`voxel-image/`): generic single-node falcon
  builder (`VBUILD_IMAGE` / `VBUILD_CARGO_BAY` / `INSTALL_SCRIPT`) + Helios
  orchestrator. Two `CAPTURE_MODE`s - `raw` (portable `.raw.xz`, streaming
  re-import) and `zfs` (fast box-local `zfs send/recv`).
- **`voxel-cp` image** - Helios + version-pinned Oxide control plane
  (`install-cp.sh`, baked through `omicron-package unpack`). Boots with all zones intact.
- **`voxel-frr` image** - Debian + FRR for routers (`install-frr.sh`, `bgpd`
  enabled). Boots to FRRouting 10.3.
- **`voxel-config`** (pure Rust, Mac-testable): generates the unnumbered-BGP RSS
  `config-rss.toml` on the fly; golden test reproduces a known-good config.
- **★ First full rack -> live Nexus (2026-06-15)** - the MVP. Unnumbered 4-gimlet
  rack on the Helios box: 7/7 propolis, RSS converged, full control plane up
  (switch, internal/external DNS, NTP, CockroachDB, ClickHouse, Crucible, Oximeter,
  **Nexus** - 107 zones). Two blockers cleared: (1) **sidecar_lite mismatch** - baked
  dendrite emits RFC 5549 `forward_v6` routes the old SoftNPU program panicked on;
  pinned the `forward_v6`-capable rev. (2) **boundary-NTP egress** - the slim topology
  dropped a4x2's `cfw` NAT node, so `router-launch` (now `voxel-init router`) NATs rack
  traffic out each router's lab uplink. Both later folded into the launch/image path.

### De-a4x2 - complete (2026-06-16)
Launch and build are both a4x2-free: per-sled config, RSS, FRR, sprockets, switch1
MGS, sp-sim, and the build-time mgs/sp/sled configs are all generated by
`voxel`/`voxel-config`, and `voxel image create <commit>` builds `voxel-cp` from a
fresh omicron clone.
- **Full a4x2 removal** - dropped the `a4x2` workspace member + `a4x2/`, the `captain`
  script, the dead `.github/buildomat/jobs/a4x2.sh` CI job, and `toml-assemble` (the
  a4x2 config-rss assembler, superseded by `voxel-rss-gen`). The `-p a4x2` in
  `build-cp.sh` is omicron's own package preset (not the repo) and stays. **a4x2 is gone.**
- **CLI consistency pass** - uniform `ls`/`list` verb; `[falcon]` config section
  (`dataset` + `rss_gen`) with flag > voxel.toml > env > default resolution (kills the
  silent-wrong-pool footgun); `image export`/`import`/`rm` (zfs send|zstd default,
  `--raw` for dd|xz). **Run-from-anywhere:** `[falcon].workdir` + `voxel.toml` discovery
  (`$VOXEL_CONFIG` -> CWD walk-up -> `~/.config/voxel` -> `/etc/voxel`); voxel `chdir`s
  to the project root so `cargo-bay/`/`.falcon/` resolve no matter where it's invoked.
- **Rustified the in-guest scripts -> `voxel-init`** - the old `gimlet-launch.sh` /
  `router-launch.sh` / `setup_ssh` are gone; an in-image `voxel-init` agent
  (cross-compiled musl, baked at `/opt/oxide/voxel-init`) does per-launch bring-up,
  invoked as `voxel-init gimlet` / `voxel-init router` via `falcon exec`. Host-side
  build scripts (`build-cp`/`build-image`/`fetch-sidecar`/`build-rss-gen`) remain shell.

### Topology + identity
- **N-sled scaling + 3-sled floor (live-confirmed 2026-06-16)** - `mgs.rs` generates
  switch0 for N sleds, `sp.rs`/bootstrap/topo scale by index; launch guards `≥3 sleds`
  + `==2 scrimlets`. A 3-sled rack booted to live Nexus, so **omicron RSS converges at
  3** (the floor is real). `GIMLETS=N voxel image create` bakes sp-sim/switch0 for N, so
  the build sets the max sled ceiling; topology sled count must match the image.
- **Coherent sled identity (46c0de8, 2026-06-23)** - SMBIOS ≡ sp-emu VPD ≡ sprockets
  trust-quorum cert serial ≡ RSS `bootstrap_sleds`, one consistent set per topology
  (`BRM4422000N`). Unblocked the wicketd trust-quorum path (see vendored
  `sprockets-tls-test-utils`).
- **FRR config generator** - per-router `frr.conf` with unnumbered
  `neighbor <iface> interface remote-as external`, pushed at launch.

### Multi-rack on one box (2026-06-23/24)
Two (or more) independent racks on a single Helios box, networked together. Both
former blockers resolved:
- **Per-rack network identity** - `NetworkConfig::for_rack(n)` + `offset_v6_prefix`
  give each rack a distinct external prefix / rack subnet / service pool / bootstrap
  base (rack 0 keeps the base `198.51.100/24`; rack 1 -> `198.51.101/24` /
  `fd00:17:2:d00::/56`), with per-rack DNS zone `rackN.oxide.test`. The host route is
  set per rack.
- **Namespaced on-disk + link state** - falcon namespaces links by deployment name
  (`--name` / `VOXEL_NAME`); `cargo-bay/` + `.falcon/` resolve per project root.
- **End-to-end** - multi-rack RSS works via both the file-init and `--wicket-setup`
  paths; launch staggers rack-by-rack (concurrent zone-init thrashes the box).
- **Switch interconnects** - `topology.interconnects` -> softnpu_links + scrimlet
  front-port budget, the substrate for cross-rack transit (Voxnet, see Next).

### Real-firmware SP/RoT emulation - `sp-emu` (2026-06-20+)
The Rust-emulator track of the SP-fidelity work (the Renode track stays Deferred).
- **`--emu-sp`** runs the whole SP fleet as real Hubris firmware on the `sp-emu`
  emulator instead of `sp-sim`; **`--emu-rot`** additionally wires the real
  `oxide-rot-1` RoT bridge (one `rot-serve` per SP). The fleet is baked into the cp
  image; `voxel sp-emu` manages emulator artifacts.
- **`voxel sp reflash` / `voxel sp debug`** - live SP/RoT firmware swap + toggle
  humility listeners.
- Caveat (live): the two-core RoT bridge starves MGS switch-id during RSS, so the
  bridge attach is deferred to post-handoff.

### Operator surfaces
- **`voxel network`** - `show` / `add-port` / `rm-port` / `validate` (`--detail`) /
  `link-up` / `link-down`.
- **`voxel rack patch` / `voxel image patch`** - surgical per-component swaps (clone
  zvol -> overlay -> re-snapshot for the image case); fast-swap a single binary/zone
  without a full rebuild.
- **`voxel launch --wicket-setup`** - drive RSS through wicketd (the real operator
  flow): suppress the staged `config-rss`, upload config + self-signed cert + recovery
  password, POST to start, and fully populate wicket's RACK SETUP page.

## Next

- **Named / heterogeneous sled set** - drop a specific sled (e.g. leave out `g2` to
  save RAM while keeping the `g0`+`g3` scrimlet pair). Today `topology.sleds` is a
  *count* expanding to a contiguous `g0..g{n-1}`. `sled-config`/`sp-sim`/bootstrap/
  falcon-topo already scale by index; the one count-fixed piece is **`mgs.rs`** (it
  embeds a static 4-sled switch template + switch0->switch1 transform - must instead
  *generate* the per-sled `[[switch.port]]` blocks + `determination` list for N).
  Empirical unknown: omicron's tolerance for sp-sim/mgs describing more sleds than boot.
- **Voxnet - rack-to-rack as a feature** - the interconnect plumbing exists
  (`topology.interconnects`); build the customer-facing multi-site model on top:
  cross-rack BGP, a shared transit fabric, or a simulated WAN, over the
  highest-bandwidth path the box affords. This is where Voxel goes past "one virtual
  rack" to "a virtual datacenter."
- **Real transit BFD** *(after the static-routing-bfd merge).* `transit_bfd = true`
  now converges, but only on the floating-static (admin distance 250) backstop in
  `frr.rs render_static`; the BFD sessions themselves never come up. Two reasons, both
  need work: (1) mgd 500s on the RSS cold-start `add_bfd_peer` and omicron swallows it
  with no retry (`early-networking/src/lib.rs`), so the sidecar peer is never programmed
  (fix upstream, or re-add once mgd is warm); (2) with one sidecar per uplink and the cr2
  path non-functional (bestpath fanout stays 1 in static mode), BFD has no alternate
  nexthop to fail over to anyway. Real failover needs both a programmed peer and a live
  second uplink.
- **Real trust quorum** *(after these merges).* Voxel sets `trust_quorum_peers: None`
  (`rss-gen/src/main.rs`), so RSS skips LRTQ init (`rack-setup/src/service.rs`) and Nexus
  stores no config (`omdb nexus trust-quorum get-config` 404s). Now that `--emu-rot` boots
  real `oxide-rot-1` firmware, try setting `trust_quorum_peers` to the sled baseboards and
  see whether the emulated fleet completes `init_trust_quorum` end-to-end.
- **Docs** - hardware reqs, Helios install guide, end-to-end usage (per docket).
- **I/O - parked** *(investigated 2026-06-16, no low-hanging fruit).* The zfs substrate
  is already sim-tuned (`sync=disabled`, `atime=off`, `compression=on`, ~96 G ARC, jumbo
  MTU 9000). The limiter is architectural: crucible's 3-way writes traverse the SoftNPU
  software dataplane + virtio-blk/propolis overhead. Voxel is a *functional* sim, not
  perf-faithful - improving this needs real hardware or a faster dataplane.

## Deferred

- **High-fidelity SP/RoT emulation via Renode** - *committed direction, not yet
  scheduled.* `sp-emu` (above) is the shipped interim; Renode is the higher-fidelity
  track - real **Hubris firmware** for the SP (STM32H753, Cortex-M7) and the RoT
  (NXP LPC55S69, Cortex-M33 + TrustZone), modeling the SP↔RoT SPI link and SP↔MGS
  management ethernet, to validate real update/firmware/attestation flows.
  - **★ Feasibility spike = GO (2026-06-16).** Renode v1.16.1 (arm64-native .NET) boots
    a real Hubris SP image: built `app/gimletlet` -> `final.elf`, booted via the bundled
    `nucleo_h753zi_hubris.resc` idiom; ~28.7M instructions in 5 s virtual, PC in app
    code, the net task configuring the ethernet MAC. **Renode's Cortex-M7 handles Hubris
    where QEMU can't** (Hubris FAQ: "QEMU? Not usefully, no"), and Antmicro ships a
    `hubris-stm32h753-udprpc` demo. The SP is proven; the RoT (LPC55/TrustZone) is the
    open, harder piece.
  - **Unblocks `pilot` on the switch** (investigated 2026-06-16): racklette switches run
    `/usr/bin/pilot` for `pilot host login`, etc. We built `pilot` and ran it in our live
    `oxz_switch`: it works, but `detect_dendrite()` keys *solely* on the presence of
    `gimletNN` SP-management-VLAN interfaces (which real dendrite creates) and discovers
    SPs via its own UDP protocol over them. Our SoftNPU sim switch has only data-plane
    `tfport*` interfaces (SP comms run `mgs-sim ↔ sp-sim` over loopback), so pilot finds
    no SPs. "pilot on the voxel switch" is gated on giving the switch zone `gimletNN`
    SP-management plumbing to each `sp-sim` - i.e. this SP-emulation work, or a
    `faux-mgs`-based bridge.

## Design decisions

- **Unnumbered BGP always.** Verified end-to-end (RSS `addr = "unnumbered"` +
  `addrconf` + `infra_ip_first/last = "::"`; mgd `UnnumberedNeighbor` + NDP +
  RFC 5549; FRR `neighbor <iface> interface remote-as external`). Removes the
  per-link addressing plan.
- **Routers = FRR-on-Debian** (`voxel-frr`), config generated on the fly. Arista
  cEOS is bring-your-own (proprietary; not built/shipped).
- **Generic images + launch-time config.** Images carry binaries only; all
  topology/identity config (RSS, FRR, sprockets, SMBIOS, sp-sim/mgs-sim, sidecar
  load) is generated and applied at launch. One image serves every topology.
- **Sidecar = SoftNPU** (falcon `softnpu_link` + `sidecar-lite` artifacts, loaded
  via `scadm` at launch). **SPs = simulated by default** (`sp-sim` + MGS sim-mode);
  real-firmware SPs available via `--emu-sp`/`--emu-rot`, with Renode as the deferred
  higher-fidelity track.

## Architecture decision (RESOLVED): config-gen is typed + travels per publish

Hand-templating omicron config on the host was wrong - it coupled Voxel to the
schema and cost an hour of one-field-per-launch thrash (`bootstrap_discovery` vs
`bootstrap_sleds`, tagged-vs-string addrs, `router_lifetime`, ...). Two decisions:

1. **Typed, not templated.** Build omicron's OWN config type (`RackInitializeRequest`
   in the light `bootstrap-agent-lockstep-types` crate; config-rss.toml is its dev/test
   file form) and let serde emit the TOML. This is what `~/oxide/topology-quest` does
   (`PutRssUserConfigInsensitive` + `toml::to_string`); the *types are the schema*, so
   mismatches are compile errors, not runtime parse failures.
2. **No host version pin - version-match per publish.** The config-gen
   (`voxel-rss-gen`) is built against the SAME omicron as the image and travels with it.
   The host tool stays version-agnostic and passes a small topology descriptor;
   `voxel-cp-19.4` carries 19.4's config-gen, etc. - correct by construction, no global
   pin. (Sled-agent config shape is auto-detected from the image's omicron.)

Why not the topology-quest crate wholesale: different topology class (CLOS-of-racks
vs single-rack+routers), it emits the *insensitive* wicket config (no certs/silo), and
it pins one rev. We reuse its *pattern* + network-config construction code.

## Quality-of-life (from docket)

- a4x2 "murders disks" - reduce write amplification on the host pool.
- Cold boot broken - sled-agent assumes ephemeral (ramdisk) state that persists
  in a4x2 because disks are regular VM images. Lever: boot the OS from a
  read-only/ramdisk image + truly-ephemeral data vdevs.
- CR nodes lose their default route to DHCP over time (mgmt-NIC DHCP client;
  separate from BGP - `nodefaultroute` / mgmt VRF).
